# Limacina Launcher

**Limacina** — это функциональный лаунчер для Minecraft, который позволяет комфортно играть как с модами, так и без них. Лаунчер поддерживает два режима работы: независимую игру и подключение к приватным серверам с собственной авторизацией на базе лаунчер-сервера Limacina.

На данный момент поддерживает версии от 1.13 и выше

## Основные возможности что будут добавляться

### Клиентская часть (Лаунчер)
* **Мультиаккаунтность:** поддержка сразу нескольких профилей пользователя.
* **Игровые проекты:** возможность создавать несколько проектов, каждый со своей версией Minecraft и независимыми файлами.
* **Тонкая настройка:** множество параметров и настроек для запуска игры. (Бета)
* **Универсальность:** играйте в одиночку, на обычных серверах или на проектах с Limacina.
* * **Интеграция с модами:** опция скачивания модов с Modrinth.

### Серверная часть (Лаунчер-сервер)
* **Авторизация:** собственная система для приватного сервера. (Бета)
* **Синхронизация:** автоматическое обновление и синхронизация файлов клиента. (Бета)
* **Кастомизация:** встроенная система установки скинов.

## Сборка

Требуется: [Node/bun](https://bun.sh), Rust toolchain, системные зависимости Tauri (Linux: `libwebkit2gtk-4.1-dev` и пр., см. [tauri docs](https://tauri.app/start/prerequisites/)).

```bash
# 1. Конфиг окружения (gitignored)
cp src-tauri/.env.example src-tauri/.env
# LAUNCHER_NAME — имя папки/приложения, LAUNCHER_SERVER_URL — адрес лаунчер-сервера

# 2. Зависимости
bun install

# 3. Разработка (Vite dev server + Rust)
bunx tauri dev

# 4. Прод-сборка (фронтенд + бинарник под текущую ОС)
bunx tauri build
```

> `.env` встраивается в бинарник на этапе компиляции (`include_str!` в `lib.rs`) — после изменения значений нужен `cargo clean`.

## Идентификатор установки

При первом старте лаунчер вычисляет идентификатор установки (`installId` в `{config_dir}/{LAUNCHER_NAME}/config.json`) и сохраняет его — повторные запуски не пересчитывают значение. Идентификатор детерминирован для конкретной машины и пользователя:

- **Windows** — серийный номер системной платы/продукта из SMBIOS (`sysinfo`, без прав администратора);
- **Linux** — серийник системного диска из `/dev/disk/by-id/` (world-readable, без прав root);
- на обеих ОС к хэшу подмешивается hostname.

Если источник недоступен (LVM/LUKS, контейнер, виртуальная машина), ID детерминированно вырождается: `/etc/machine-id` (Linux) или `MachineGuid` из реестра (Windows), в крайнем случае — хэш от пути конфигурации и ОС. Сырые значения железа не покидают машину: в конфиг и на сервер уходит только производный ID в формате `v1-<32 hex>`.

ID меняется, если меняется железо-источник (системный диск / плата) или hostname; переустановка лаунчера и перезапуск сохраняют его.

К каждому запросу к лаунчер-серверу (авторизация, конфиг проекта, синхронизация файлов и модов, скины, модели, обновления) прикладывается заголовок `X-Launcher-Id`. Внешние источники (Modrinth, манифесты Mojang, Adoptium) его не получают.
