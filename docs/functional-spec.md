# Функциональная спека лаунчера Limacina

Статус: описательный документ. Фиксирует поведение лаунчера на уровне пользователя: экраны, сценарии, состояния, тексты. Реализацию (IPC, сторы, файлы) документ не описывает. При расхождении с кодом правится либо спека, либо считается багом кода.

Тексты кнопок, ошибок и уведомлений приведены дословно по состоянию кода на 2026-10-14 (ветка `release-0.6.x`). При изменении текстов в шаблонах соответствующий раздел обновляется. Внутри цитат интерфейсных строк сохранена их фактическая пунктуация.

## 1. Понятия и режимы

* **Проект** и **профиль** являются синонимами. "Проект" употребляется в техническом смысле (конфиг, папка), "профиль" в пользовательском интерфейсе (кнопка "Добавить профиль"). Проект представляет собой изолированную установку игры со своей версией Minecraft, загрузчиком модов, файлами, настройками и скинами.
* **Аккаунт**. Сохранённая пара логина и пароля игрока. **Сессия**. Активный вход конкретного аккаунта в конкретном проекте.
* **Сервер лаунчера**. Бэкенд, с которым лаунчер синхронизируется. Не путать с игровым сервером Minecraft.
* Три режима определяют поведение почти каждого экрана:
  * **Онлайн-проект** (`online: true`). Профиль, подключённый к серверу: аккаунты, синхронизация файлов, проверка доступности сервера.
  * **Офлайн-проект** (`online: false`, "Одиночная игра"). Локальный профиль: без аккаунтов и сервера, скины и модели хранятся локально, видна вкладка "Моды".
  * **Офлайн-сборка**. Сборка лаунчера без сервера лаунчера: автообновление и откат версий отключены, первый запуск требует создания локального профиля.

## 2. Старт приложения и первый запуск

### 2.1. Инициализация

При старте показывается полноэкранный прелоадер (минимум 1 с). Пока идёт автообновление (включено `autoUpdate`, не офлайн-сборка), текст прелоадера меняется: "Проверка обновлений...", затем "Скачивание обновления до v{X}...", затем "Обновление завершено, загрузка...".

Ветвления:

| Условие | Результат |
|---|---|
| Нет конфига лаунчера | Переход на Setup (шаг 1) |
| Офлайн-сборка и нет ни одного проекта | Переход на Setup (шаги 1 и 2) |
| Ошибка инициализации | Экран "Ошибка запуска" и "Не удалось загрузить данные лаунчера" с текстом ошибки. Кнопки "Повторить" и, если конфига нет, "Настроить лаунчер" |
| Ошибка автообновления | Тост "Не удалось проверить обновления" или "Не удалось обновить лаунчер", загрузка продолжается |

После инициализации стартуют фоновые механизмы: стрим логов консоли, стрим шагов запуска, системные уведомления, опрос статуса игрового сервера (60 с) и доступности сервера лаунчера (30 с с backoff), синхронизация игровой сессии.

### 2.2. Setup (первый запуск)

Полноэкранный маршрут без каркаса. Два шага, индикатор "Папка установки -> Профиль".

Шаг 1 "Настройка лаунчера": поле пути к папке хранения файлов (readonly, плейсхолдер "Выберите папку", предпросмотр "Путь установки" из выбранной папки и имени лаунчера), кнопки "Обзор" и "Сохранить" (недоступна без пути). После сохранения лаунчер переходит к шагу 2, если нужен офлайн-профиль, иначе на главный экран. Если система сообщает о reduced motion, анимации отключаются автоматически.

Шаг 2 "Добавить профиль": встроенная форма добавления профиля (см. раздел 5, без кнопки "Назад"). Пока офлайн-сборка остаётся без профиля, пользователь удерживается на Setup автоматически.

## 3. Каркас приложения

Зоны: шапка (селектор проекта, индикатор игрового сервера, переключатель темы), сайдбар слева, контент-карточка с баннером над ней, версия `v{X}` в правом верхнем углу.

* **Селектор проекта** виден, когда есть хотя бы один проект. Переключение доступно при наличии более одного. Блокируется во время запуска игры, сессии, авторизации и переключения (см. 12.2).
* **Индикатор сервера** (только онлайн-проект): зелёная точка, счётчик `{онлайн}/{максимум}` игроков, тултип "Игровой сервер доступен ({версия})".
* **Баннер недоступности** (онлайн-проект, сервер лаунчера недоступен): "Сервер лаунчера недоступен, запуск и синхронизация файлов приостановлены. Мы продолжаем проверять соединение."
* **Сайдбар**: "Аккаунты", "Добавить профиль", "Моды" (только офлайн-проект), "Настройки" (раскрывающаяся группа: "Лаунчер", "Проект", "Игра", "Аккаунт", "Скин", "Модель"), "Дебаг" (только при включённом debugMode). Недоступные подпункты настроек показываются притушенными с тултипом-причиной: "Не удалось загрузить настройки проекта", "Недоступно в офлайн-режиме", "Проект ещё не инициализирован", "Требуется авторизация".
* **Автоперенаправления**: выход из офлайн-проекта при открытых "Модах" ведёт на "Аккаунты". Выключение debugMode при открытой вкладке "Дебаг" ведёт на "Аккаунты". Появление необходимости офлайн-сетапа ведёт на Setup. Неизвестный маршрут ведёт на "Аккаунты".
* **Адаптивность**: до 991px сайдбар превращается в компактную горизонтальную панель с подписями под иконками, до 575px остаются только иконки.

## 4. Главный экран ("Аккаунты")

Приоритет отображения: прелоадер "Смена проекта...", затем пустое состояние, затем экран сессии, затем экран прогресса запуска, затем экран аккаунта с авторизацией.

**Пустое состояние** (нет ни одного проекта): "Профилей нет", "В лаунчере ещё нет ни одного проекта", объяснение, что такое профиль, кнопка "Добавить профиль".

**Экран аккаунта**: аватар-идентикон из ника, подпись "Текущий аккаунт" или "Выберите аккаунт", имя (сессия, затем выбранный, затем первый из сохранённых, затем "Не выбрано"). Кнопка **"Играть"** недоступна без сессии и при недоступном сервере. В последнем случае над ней виден текст: "Сервер лаунчера недоступен, запуск заблокирован, ждём восстановления соединения". Ошибки выбора аккаунта и запуска показываются красным боксом под шапкой.

**"Сменить аккаунт"** открывает выпадающее меню: скелетоны при загрузке, строка ошибки "Не удалось загрузить список аккаунтов" с кнопкой "Повторить", строки аккаунтов (идентикон и ник, галочка у активного, кнопка удаления), пункт "+ Ввести новый" с формой авторизации. Выбор аккаунта при ошибке откатывается с показом ошибки. Удаление идёт через confirm "Вы хотите удалить аккаунт {ник}?". Успех подтверждается тостом "Аккаунт удалён". Удаление активного аккаунта сбрасывает сессию.

Форма авторизации открывается сама, когда аккаунтов нет. Кнопка "Назад к аккаунтам" видна, когда есть что показывать.

## 5. Авторизация

Вкладки **"Вход"** и **"Регистрация"**. В офлайн-проекте вкладок нет, показывается только форма входа без пароля, кнопка называется "Играть".

**Вход**: поля "Никнейм" и "Пароль" (скрыт офлайн), чекбокс "Сохранить данные", кнопка "Войти". Кнопка активна при нике от 4 символов, онлайн дополнительно требует пароль от 6 символов. В поле ника подставляется первый сохранённый логин. Успех подтверждается тостом "Авторизация прошла успешно", пароли стираются, сессия активна.

**Регистрация**: поля "Логин", "Пароль", "Повторите пароль". Подсказки требуют логин от 4 символов и пароль от 6, словоформы склоняются, при расхождении полей показывается "Пароли не совпадают". Успех подтверждается тостом "Аккаунт успешно создан. Ожидайте одобрения администратора.", происходит возврат на вкладку "Вход".

Ошибки сервера показываются в форме как есть (текст бэкенда). На время отправки кнопка переходит в состояние загрузки со спиннером, повторная отправка заблокирована.

## 6. Добавление профиля

Переключатель типа: **"Сервер"** и **"Одиночная игра"** (стрелки влево и вправо, по умолчанию "Сервер").

* **Сервер**: поле "Адрес сервера" (плейсхолдер "mc.example.com:3000"), кнопка "Добавить". Подзаголовок: "Введите адрес сервера: версия, сборка и моды загрузятся с него автоматически". Успех подтверждается тостом: Сервер "{имя}" добавлен. Происходит переход на "Аккаунты".
* **Одиночная игра**: поля "Название профиля" и "Версия Minecraft" (дропдаун, заблокирован, пока список грузится или пуст, чекбокс "Показывать снапшоты" перезагружает список), "Загрузчик модов" ("Без загрузчика (Vanilla)", Fabric, Forge, NeoForge), "Версия загрузчика" (только для не-vanilla, автовыбор первой). Успех подтверждается тостом: Профиль "{имя}" создан.

Ошибки загрузки списков версий показываются красным боксом в форме. Если под выбранную версию Minecraft нет версий лоадера, форма показывает "Нет версий {лоадер} для Minecraft {версия}". После создания профиль становится текущим, состояние аккаунтов и запуска сбрасывается, сессия завершается.

## 7. Запуск игры

### 7.1. Предпусковые проверки

Проверки выполняются по порядку, срабатывание сопровождается тостом:

1. Уже идёт запуск. Тихий игнор без тоста.
2. Игра уже запущена. Тост "Игра уже запущена".
3. Сервер лаунчера недоступен. Тост "Сервер лаунчера недоступен, запуск невозможен".
4. Идёт проверка целостности. Тост "Идёт проверка целостности, запуск невозможен".
5. Ошибка опроса состояния игры. Тост "Не удалось проверить состояние игры, запуск заблокирован".

### 7.2. Экран прогресса

Заголовок "Подготовка запуска", в конце "Запуск игры". Полоса общего прогресса и список шагов с индикаторами (ожидание, выполнение, готово, ошибка). Активный шаг показывает детализацию от бэкенда и счётчик "текущий/всего". Пропущенные шаги несут флаг `skipped` и выполняются без прогресса. Подсказки: "Игра запускается, окно откроется автоматически" (последний шаг) и "Запуск был прерван перезагрузкой окна, отмените и запустите заново".

Кнопка **"Отменить запуск"** видна, только пока процесс игры не запущен: первое нажатие ставит отмену в очередь (кнопка меняется на "Завершаем текущий шаг..."), фактическая отмена происходит по завершении текущего шага. Прерванный запуск отменяется сразу. Ошибка шага: очередь событий дображивается, шаг помечается ошибкой, текст возвращается на главный экран красным боксом.

### 7.3. Состав шагов

Каталог шагов (отображаемые названия): "Проверка Java", "Скачивание Java", "Распаковка Java", "Получение списка файлов", "Скачивание файлов", "Файлы сервера", "Получение списка модов", "Проверка и скачивание модов", "Очистка лишних модов", "Моды", "Загрузка манифеста версий", "Загрузка манифеста версии", "Клиент игры", "Библиотеки игры", "Нативные библиотеки", "Загрузка индекса ресурсов", "Загрузка ресурсов", "Установка мод-лоадера" (для конкретного лоадера: "Установка Fabric", "Установка Forge", "Установка NeoForge"), "Подготовка конфигурации", "Запуск процесса игры", "Ожидание окна игры".

* Первый запуск проекта (установка): Java -> (онлайн: файлы сервера) -> (не-vanilla: моды) -> Minecraft (манифесты, клиент, библиотеки, нативные библиотеки, ресурсы, лоадер) -> конфигурация -> процесс -> окно.
* Повторный запуск: (онлайн: файлы сервера) -> (не-vanilla: моды) -> конфигурация -> процесс -> окно. Уже установленные группы пропускаются по журналу установки. Сбои журнала установку не прерывают, возможна повторная загрузка файлов.
* Каждый шаг показывается минимум 500 мс. Если при старте лаунчера бэкенд сообщает о запущенной игре, которую фронт не знает, включается состояние "прерванный запуск" (см. подсказку в 7.2).
* При включённой настройке "Закрывать лаунчер после запуска игры" лаунчер закрывается после шагов запуска.

### 7.4. Сессия

Экран "Игра запущена": карточка с точкой и никами запущенных игр, под ней кнопка "Назад к аккаунтам". Экран открывается только после завершения всех шагов запуска, включая "Ожидание окна игры", до этого виден экран прогресса. Кнопка возвращает к выбору аккаунта, не прерывая сессию. Ники при этом выровнены по левому краю карточки.

Поддерживается несколько одновременных сессий с разными аккаунтами одного проекта: пока игра запущена, "Назад к аккаунтам" -> выбор другого аккаунта -> повторный запуск разворачивает вторую игру параллельно первой. Повторный запуск того же аккаунта блокируется тостом "Этот аккаунт уже в игре". Экран сессии показывает все запущенные ники (заголовок "Игра запущена", при нескольких "Игры запущены ({N})"), после нового запуска экран сессии показывается снова. Пока запущена хоть одна игра, блокируются смена проекта и удаление проекта.

Трей: тултип "{лаунчер}, игра запущена ({ник})", при нескольких "{лаунчер}, игры запущены ({N}): {ник1}, {ник2}". Пункт меню "Игра запущена: {ник}" или "Игры запущены ({N}): {ники}". Игровая иконка трея и Discord-присутствие держатся, пока жива хотя бы одна игра (присутствие показывает последний запуск), выход последней возвращает обычный статус.

Выход из игры: событие приходит с ником завершившейся сессии, статус остальных не меняется. Если окно было скрыто, приходит системное уведомление "Игра {ник} закрыта, лаунчер ждёт в трее". Если окно было видно и выход произошёл с ошибкой, показывается тост "Игра {ник} завершилась с ошибкой (код {N})" либо "Игра {ник} была аварийно завершена" с причиной. После рестарта вебвью список запущенных сессий восстанавливается с бекенда.

Дебаг-консоль: строки каждой игры помечаются префиксом "[MC|{ник}]", потоки сессий идут в единый список, разделение по табам вынесено в отдельную задачу. Кнопка "Убить процесс" завершает все запущенные игры.

## 8. Проверка целостности

Точка входа: Настройки, "Проект", "Обслуживание", кнопка "Проверить". Проверка только ручная, автозапуска нет.

Взаимные блокировки с запуском (тосты): "Проверка целостности уже выполняется", "Идёт запуск игры, проверка целостности недоступна", "Идёт проверка целостности, запуск невозможен".

Модальный попап **"Проверка целостности файлов"**: полоса прогресса и шаги (онлайн: MC-шаги, "Файлы сервера", "Моды", офлайн: только MC-шаги). Закрытие возможно клавишей Esc, кликом по фону и кнопкой "Закрыть". Закрытие во время проверки не останавливает её, результат приходит тостом.

Итоги: "Все файлы в порядке", "Файлы восстановлены", "Не удалось восстановить {N} файлов" (красным, со списком), статистика "проверено: {N}", "повреждено: {N}", "отсутствовало: {N}", "восстановлено: {N}". Кнопка "Проверить снова".

## 9. Настройки

### 9.1. Уровни настроек

Настройки делятся на уровни действия: страница "Лаунчер" влияет на всё приложение, страницы "Проект" и "Игра" — только на текущий профиль. "Аккаунт", "Скин" и "Модель" тоже относятся к проекту и работают с пользовательским контентом.

| Страница | Уровень действия | Доступные функции |
|---|---|---|
| "Лаунчер" | Всё приложение, общие для всех проектов | Папка установки; автозапуск с системой; закрытие после запуска игры; сворачивание в трей; системные уведомления; статус в Discord; автообновление и откат версии; ограничение скорости загрузки; сохранение старых конфигов Minecraft; страница отладки; анимации; тема |
| "Проект" | Текущий профиль | Версия Minecraft, загрузчик и его версия; автозаход на сервер; память min-max; пресет JVM; свои JVM-аргументы; выбор Java (путь, дистрибутив, версия); url для подключения игроков; проверка целостности; очистка конфигов игры; удаление проекта |
| "Игра" | Текущий профиль, записи в options.txt Minecraft | Графика; звук; чат; ресурспаки; импорт общих настроек; сохранение как общих |
| "Аккаунт", "Скин", "Модель" | Текущий профиль, пользовательский контент | Смена пароля; скин: 3D-просмотр, загрузка, сброс; модель CPM: загрузка, анимации |

### 9.2. Общие механизмы

* Страницы собираются из складных секций, состояние схлопнутости запоминается в localStorage.
* **Панель сохранения** (липкая снизу): кнопка "Сохранить" подсвечивается при несохранённых изменениях и блокируется при загрузке, сохранении или ошибке загрузки. На странице "Игра" рядом есть кнопка "Сохранить глобально".
* **Dirty-guard**: уход с грязной вкладки "Лаунчер" или "Игра" (кнопкой или сменой проекта) вызывает confirm "На вкладке есть несохранённые изменения. Покинуть её?".
* Загрузка показывается скелетонами. Ошибка выглядит как строка "Не удалось загрузить ..." с кнопкой "Повторить", сохранение блокируется. Успешное сохранение подтверждается тостом "Настройки сохранены", на странице "Игра" тостом "Настройки игры сохранены".

### 9.3. "Лаунчер"

Секции: "Расположение" (путь к папке лаунчера, кнопка "Обзор"), "Запуск и закрытие" (автозапуск с системой, "Закрывать лаунчер после запуска игры", "Сворачивать в трей при закрытии"), "Уведомления" (системные уведомления при свёрнутом лаунчере, включены по умолчанию, "Показывать статус в Discord", включено), "Загрузка и обновление" (автообновление, выключено по умолчанию, ограничение скорости в КБ/с, пустое поле означает "Без ограничений", нецелое или неположительное значение даёт тост "Ограничение скорости: целое число от 1 до {N} КБ/с"), "Продвинутое" (сохранять старые конфиги Minecraft, показывать страницу отладки), "Внешний вид" ("Анимации интерфейса", сохраняется сразу, при первом запуске отключается сама при reduced motion, а также выбор темы: 5 семейств в тёмной и светлой модификациях, применяется мгновенно), "Обновление лаунчера" (скрыта в офлайн-сборке, см. 12.4).

Особенности сохранения: автозапуск применяется к ОС отдельным шагом, ошибка даёт тост "Не удалось включить/выключить автозапуск", тост успеха в этом случае не показывается. При ошибке сохранения конфиг перечитывается с бэкенда.

### 9.4. "Проект"

* **"Сборка"** (read-only, кроме отмеченного): версия Minecraft, загрузчик, версия загрузчика (редактируемая), кнопка "Обновить списки версий", чекбокс "Автозаход на сервер при запуске".
* **"Запуск"**: двойной слайдер "Память (min-max)" (шаг 512 МБ, формат "512M-8G", min не превосходит max), "Пресет" JVM ("По умолчанию", "Базовая оптимизация", "Слабый ПК" на Java 8+, "Максимальная оптимизация" на Java 21+, недоступные по версии Java пресеты скрываются кроме активного), поле "JVM аргументы" с запретом кавычек ("Кавычки не поддерживаются: аргументы разделяются пробелами или запятыми и передаются процессу напрямую, как есть"), сохранение с ошибкой блокируется тостом.
* **"Java"**: путь к Java (диалог выбирает папку JDK, в поле подставляется найденный `bin/java`, рядом показывается версия; папка без `bin/java` даёт тост с ошибкой, поле не меняется), попап "Загрузка Java": вендор (список дистрибутивов), версия (пусто означает "Авто (на основе MC)"), чекбокс "Заменить Java по умолчанию". Во время скачивания закрытие попапа заблокировано. Успех приносит системное уведомление "Java установлена". Версия "Авто (на основе MC)" берётся из манифеста Minecraft: Java 8 до 1.16.5 включительно, Java 17 для 1.17–1.20.4, Java 21 начиная с 1.20.5, Java 25 начиная с 26.1. Верхнюю границу совместимости задаёт стек загрузчика, а не лаунчер: например, для Minecraft 1.16.5 с Forge максимальная совместимая версия — Java 16 (штатно устанавливается Java 8, а Java 17 и новее стек Forge этого поколения не поддерживает), поэтому ручной выбор версии выше авто на старых проектах может привести к отказу запуска.
* **"Подключение к серверу"** (только онлайн): кнопка "Получить url для подключения сервера", после нажатия появляется url с кнопкой "Скопировать" (тост "Ссылка скопирована") и подсказкой, что ссылку отправляют игрокам.
* **"Обслуживание"**: проверка целостности (см. раздел 8), "Очистить конфиги игры" (confirm, тост с результатом), "Удалить проект" (если проект не зафиксирован сборкой). Блокировки: "Нельзя удалить проект, пока запущена игра", "Дождитесь завершения запуска игры". Confirm: "Удалить проект "{имя}"? Папка с игрой, модами, конфигами и сохранениями будет удалена безвозвратно". После удаления лаунчер переходит на другой проект или на "Добавить профиль".

### 9.5. "Игра"

Настройки Minecraft сохраняются в options.txt проекта и применяются при следующем запуске игры; страница доступна до первого запуска проекта, поэтому ресурспаки и остальные настройки можно выбрать заранее (подсказка об этом есть на странице). Файл options.txt создаётся и выравнивается по установленному клиенту при установке игры: в него пишется ключ version (Data version клиента), и настройки, сохранённые до установки, вписываются в тот же момент (до установки они хранятся в памяти лаунчера, о чём предупреждает вторая строка подсказки). Тогда же нарратор принудительно выключается (ключи narrator:0 и onboardAccessibility:false): приветственный экран нарратора, который Minecraft показывает при первом запуске, иначе включил бы его сам; те же ключи переписываются перед каждым запуском игры. Секции: "Графика" (FOV от 30 до 110, яркость, дальность прорисовки и симуляции, максимум FPS от 10 до 260, качество графики, mipmap, частицы, облака, масштаб интерфейса, вертикальная синхронизация, тени существ, мягкое освещение, полный экран), "Звук" (десять слайдеров громкости от 0 до 1), "Чат" (видимость, масштаб, ширина, прозрачность, задержка от 0 до 6 с шагом 0.5, цвета, ссылки, подтверждение перехода по ссылкам), "Ресурспаки" (чекбоксы по файлам из папки, пустое состояние: "В папке resourcepacks нет ресурсных пакетов").

Кнопка "Импортировать общие" видна, если глобальный эталон существует, и даёт тост "Общие настройки подставлены, не забудьте сохранить". "Сохранить" пишет настройки в проект (до установки игры — тост "Настройки игры сохранены: они применятся при установке игры", значения ждут установки в памяти лаунчера), "Сохранить глобально" делает их эталоном (тост "Настройки сохранены как общие").

### 9.6. "Скин"

Прелоадер "Загрузка скина...". Переключатель модели "Классик"/"Слим" (в офлайне сохраняется сразу). 3D-вьюер. Кнопки "Загрузить скин" и "Заменить скин", "Сохранить" (только онлайн, тост "Скин успешно загружен"), "Сбросить скин" (confirm). Drag-and-drop с валидацией: формат .png до 256 КБ ("Размер файла не должен превышать 256 КБ (загружено {N} КБ)"), размеры "64x32, 64x64 и кратные им". Список "Загруженные скины" (онлайн): активировать, копировать ссылку, удалить с confirm. Подсказка офлайна: "Локальный профиль: скин сохраняется на этом компьютере и применяется при запуске игры".

### 9.7. "Аккаунт"

Read-only поле "Никнейм". Смена пароля (текущий, новый, повтор). Ошибки: "Пароли не совпадают", "Новый пароль совпадает с текущим" либо текст сервера. Кнопка активна при достаточных длинах (от 6 символов) и несовпадении со старым. Успех подтверждается тостом "Пароль изменён", сессии на других устройствах завершаются (подсказка на форме). В офлайн-проекте страница скрыта.

### 9.8. "Модель" (CPM)

Загрузка `.cpmproject` до 2 МБ через drag-and-drop или файловую кнопку. Онлайн: кнопка "Отправить" конвертирует модель, загружает на сервер и в игру (тост "Модель добавлена в игру"). Офлайн: кнопка "Сохранить в игру" (тост "Модель сохранена в игру"). 3D-вьюер с текстурой модели и панель анимаций (мультиселект анимаций, "Пауза" и "Воспроизвести", "Повторять анимацию", замедление и ускорение "N×", без выбранной анимации всё заблокировано). Чекбокс "Показать пустые слои" и список слоёв видимости. Открытие `.cpmproject` из ОС открывает эту вкладку с файлом.

Конвертация переносит в игру анимации проекта: ванильные позы (по списку поз игры), кастомные позы, жесты, слои, значения и staged-анимации вместе с их настройками (приоритет, интерполятор, зацикливание, additive, порядок, группа, mustFinish, видимость кнопки) и маской слоёв скина из `anim_enc.json`, поэтому модель движется в игре так же, как в превью. Если модель управляется слоями скина, а `anim_enc.json` в проекте нет или в нём меньше двух свободных слоёв, анимации сохраняются без привязки к слоям (жест доступен всегда), а предупреждение уходит в консоль отладки — установка модели при этом не прерывается.

Важно: модель в любом случае устанавливается в саму игру — файл попадает в player_models проекта и отмечается выбранной в настройках CPM, поэтому её можно сразу выбрать в меню CPM внутри Minecraft, независимо от отправки на сервер. Видимость другим игрокам определяется сервером: чтобы модель увидели остальные участники онлайн-проекта, сервер должен работать на специальном форке CPM — его серверная часть передаёт окружающим ссылку на модель, а их клиенты скачивают модель с сервера лаунчера. Без такого форка модель видна только самому игроку.

## 10. Моды (Modrinth)

Вкладка доступна только в офлайн-проекте. Подсказка: "Моды Modrinth для одиночного профиля (Minecraft {версия}). Требуемые зависимости устанавливаются автоматически."

Два режима (segmented-переключатель со стрелками влево и вправо):

* **"Каталог"**: поиск по Enter и кнопке "Найти", сортировка (релевантность, загрузки, подписки, новые, обновлённые), мульти-селект категорий (11 значений со сбросом). Смена фильтров перезагружает список с первой страницы. Счётчик "Найдено: {N}". Пустой результат: "Ничего не найдено". Строка результата: иконка, название, бейдж установленной версии и/или "Доступно: {версия}", описание, строка "{N} загрузок · {автор}", действия и "Подробнее". Пагинация по 20 позиций, при более чем 7 страницах свёрнутая.
* **"Установленные"**: счётчики модов и обновлений, "Открыть папку модов", "Проверить обновления". Пустое состояние: "Пока ничего не установлено, найдите моды в каталоге". Строка: версия, имя файла, "Доступно: {версия}", "Обновить" или бейдж "Установлен", "Удалить" с confirm "Удалить этот мод из профиля?".

Действия в обеих вкладках: "Скачать", "Обновить" или бейдж "Установлен". Во время операции кнопка мода показывает загрузку, остальные действия блокируются, одновременно идёт одна операция. Попап проекта ("Подробнее"): статистика, совместимость с клиентом и сервером, лицензия, даты, категории, описание, тело проекта (Markdown, ссылки открываются во внешнем браузере), список версий с changelog, внешние ссылки (исходный код, баг-репорт, вики, Discord). Смена проекта полностью сбрасывает состояние вкладки.

## 11. Дебаг-консоль

Видна только при debugMode. Показывает поток логов игры и стартовый буфер до 2000 строк (ANSI-коды вырезаются, backlog догружается при открытии вкладки), виртуализированный список с автоскроллом (отключается при ручной прокрутке, кнопка "К последней строке"). Фильтры: поиск по подстроке и тумблер "Только ошибки". Пустое состояние: "Логов пока нет" или "Под фильтр ничего не подошло". Ошибка стрима: "Стриминг логов недоступен: {ошибка}" и кнопка "Повторить". Действия: "Копировать" (копирует отфильтрованные строки) и "Убить процесс" (без запущенной игры заблокирована, в процессе показывает "Завершаем...", ошибки дают тосты "Игра не запущена" и "Не удалось завершить процесс игры: ...").

### 12.6. Телеметрия: идентификатор установки

Лаунчер отправляет серверу **идентификатор установки** — обезличенный маркер компьютера. Его единственное назначение: помочь серверу определять «твинки» — несколько аккаунтов, играющих с одного компьютера.

* **Как считается.** При первом запуске из имени компьютера и серийного номера железа (при недоступности — системного идентификатора ОС) вычисляется хеш SHA-256 с фиксированной солью, обрезается и получает префикс версии ("v1-…"). Исходные данные наружу не уходят: сервер видит только необратимый хеш. Если подходящих источников нет, используется детерминированный запасной вариант, чтобы идентификатор оставался стабильным.
* **Куда отправляется.** Со всеми запросами к серверу лаунчера (авторизация, конфиг, файлы, моды, скины, обновление) в заголовке `X-Launcher-Id`. В офлайн-проекте и офлайн-сборке серверных запросов нет — идентификатор остаётся на компьютере.
* **Стабильность.** Идентификатор вычисляется один раз и хранится в конфиге лаунчера: переустановка лаунчера его сохраняет, смена железа или имени компьютера даёт новый.
* **Границы.** Телеметрия ограничена самим идентификатором: помимо штатных данных авторизации и синхронизации, лаунчер не отправляет содержимое игровых файлов, историю действий или что-либо ещё.

## 13. Безопасность и целостность

### 13.1. Проверка хешей при установке и запуске

Файлы игры сверяются с хешами источника на шагах установки и запуска, до старта процесса игры:

* клиент, библиотеки, нативные библиотеки, ресурсы и их индекс — по SHA-1 из манифеста Mojang;
* файлы сервера и моды — по SHA-1, который присылает сервер лаунчера;
* файлы без хеша у источника (jar загрузчиков и установщики) — по хешу, записанному при первой установке;
* authlib-injector — по SHA-256.

Скачивание атомарно: файл сначала пишется во временный файл и переименовывается только после успеха, поэтому обрыв связи не оставляет недокачанный файл под видом готового. Отсутствующие и не совпавшие по хешу файлы докачиваются автоматически; если библиотека отсутствует и скачать её нельзя, запуск прерывается ошибкой "Библиотеки не найдены: {файлы}. Запустите проверку целостности в настройках проекта". Повторные запуски пропускают уже установленные группы по журналу установки, поэтому полная сверка выполняется при установке и вручную (см. раздел 8).

### 13.2. Моды: сверка и очистка перед запуском

В онлайн-проекте с загрузчиком модов перед запуском папка mods приводится к списку сервера: сначала скачиваются отсутствующие и изменившиеся моды (сверка по SHA-1), затем шаг "Очистка лишних модов" удаляет все файлы в папке, которых нет в списке сервера. Это даёт всем игрокам проекта одинаковый набор модов и убирает посторонние jar, попавшие в папку вручную. В офлайн-проекте состав модов определяет только пользователь через каталог Modrinth, автоочистка не выполняется.

### 13.3. Хранение учётных данных

Пароли и токены хранятся в системном хранилище секретов: Windows Credential Manager или Secret Service (GNOME Keyring / KWallet). Резервное хранилище на диске (файл с доступом только для владельца) хранит только токены обновления и идентификаторы аккаунтов — пароли туда не попадают никогда; если системное хранилище недоступно, пароль не сохраняется вовсе. Записи резервного хранилища дополнительно шифруются секретом из системного хранилища; нечитаемая запись сбрасывается и требует повторного входа.

### 13.4. Валидация JVM-аргументов

Проверку по белому списку проходят все JVM-аргументы запуска — и заданные в проекте, и пришедшие из манифеста версии (Mojang или загрузчика): разрешены параметры памяти, GC-тюнинга, ограниченный набор системных свойств, модульные и экстра-опции JDK (штатные "--enable-native-access=ALL-UNNAMED" и "--sun-misc-unsafe-memory-access=allow" из манифеста новых версий игры). Агенты и отладочные параметры ("-javaagent", "-agentlib", "-Xdebug" и подобные) отклоняются ошибкой "В JVM-аргументах проекта указан запрещённый параметр «{аргумент}»: разрешены только параметры памяти, GC-тюнинга, системные свойства из списка, модульные и экстра-опции JDK. Удалите его в настройках проекта"; кавычки во вводе блокируются сразу (см. 9.4). В релизных сборках лаунчер добавляет к игре "-XX:+DisableAttachMechanism": к процессу игры нельзя подключиться отладчиком извне.

### 13.5. Защита путей и обновлений

* Пути файлов, приходящие с сервера лаунчера (файлы проекта, моды), проверяются: обход каталогов (".."), абсолютные пути и буквы дисков отклоняются — файл не может быть записан вне папки проекта.
* Архивы Java распаковываются с проверкой путей внутри архива и лимитом суммарного размера распаковки.
* Артефакты автообновления подписаны, подпись проверяется перед установкой (см. 12.4); неподписанное или изменённое обновление не применяется.
* Отправляемый серверу идентификатор установки обезличен и служит только для определения твинок (см. 12.6).
